## High-priority recommendation relevance case (RD-11, with RD-52 / RD-73 / RD-62)

**Reader:** residential cleaning company owner.

**Stated problem:** inconsistent customer lead flow leaves cleaners without full schedules or reliable earnings. Good cleaners leave; the owner repeatedly recruits, fills cleaning shifts and does admin/marketing, preventing growth. Prioritize reliable local customer acquisition, recurring demand, capacity/scheduling and the link to talent retention. Do not reduce the problem to generic entrepreneurship, creative writing or hiring alone.

**User-reported recommendations:**

1. The Creator's Code: The Six Essential Skills of Extraordinary Entrepreneurs — Amy Wilkinson
2. Wired for Story: The Writer's Guide to Using Brain Science to Hook Readers from the Very First Sentence — Lisa Cron
3. Innovation and Entrepreneurship — Peter F. Drucker
4. Read Me: 10 Lessons for Writing Great Copy — Roger Horberry
5. D&AD. The Copy Book — Various

The list is reported by Michael; the exact stored profile, uploaded CSV, catalog snapshot and ranking trace were not available for replay. It is not proof that every title is irrelevant. The set needs a clear, defensible connection to the specific problem.

### Investigation and acceptance

- Preserve the reader's causal chain when extracting the confirmed conversation into the stored profile. Compare the submitted problem, summary and saved fields; do not let staff-retention symptoms erase the lead-flow constraint.
- Replay the same profile before and after a representative Goodreads import using an isolated test account/database. Inspect which endpoint and engine path ran, persisted rows, read-book exclusions, preference/category effects and stale-cache behavior.
- Inspect candidate catalog coverage, business-model normalization, detailed topic/promise metadata, scores and tie-breaking. Broad “sales/marketing” domain overlap is a hypothesis to examine, not a verified root cause.
- Existing code includes broad domain scoring in `_user_problem_domains` / `_score_from_problem` and history/category scoring paths. Confirm the actual runtime path before changing weights.
- Rank books with direct support for the stated bottleneck above weak broad-category matches where the catalog supports that distinction. Explanations must cite actual book content/metadata and the reader's context, not merely restate “marketing.”
- If the catalog cannot supply strong matches, communicate uncertainty or offer fewer well-supported choices; do not fill five slots with confident weak matches.
- Verify reading history has a measurable, intended effect without overwhelming the current problem. Imported already-read titles should not be recommended as new next reads.
- Add a reproducible ranking regression case; obtain Michael's review of the resulting set. Automated API success is not recommendation-quality acceptance.
